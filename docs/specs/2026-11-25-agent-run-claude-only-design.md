# Agent Run! 只接 Claude Code 方案

日期:2026-11-25 · 状态:待确认

实地检查(2026-11-25,开发机):`~/.agent-run/`、`~/.codex/hooks.json`、`~/.dsh` 都不存在,这台机器目前没有任何需要清理的旧 hook;§6 的清理与提示是给已经装过旧版的机器准备的。

## 1. 目的

使用者只用 Claude Code。现在的首页有一整排计数格分给 Codex、dsh,而 Claude Code 的订阅用量要按下键切到专用页面才看得到。本方案:

- 采集端只接 Claude Code,不再采集 Codex、dsh;
- 首页底部三格改为 Claude Code 的 5 小时用量、每周用量、后台运行,开机即可看到用量;
- 去掉 Codex 专用页面,上下键只在首页与 Claude Code 页面之间切换。

## 2. 目标、非目标、反目标

**目标**

- 首页一眼看到 5 小时与每周用量的百分比。
- 电脑上不再安装、执行 Codex 与 dsh 的 hook,也不再扫描它们的会话文件。
- 协议不变:新旧固件与新旧采集端任意搭配都能工作。

**非目标**

- 不改宠物场景、大数字、速度条、等你处理、未连接、设置菜单、省电与勿扰。
- 不改协议格式,不升 `proto` 版本。
- 不保留“以后再接回 Codex”的开关或配置项。

**反目标**(即使功能正常也算失败)

- 刷新固件前后,设备显示“未连接”或整帧被丢弃。
- 升级后使用者的 `~/.codex/hooks.json` 里还残留 agent-run 的条目且没有办法清掉。
- 首页布局改动导致 LVGL 内存池余量不足(现约 3.3 KB)。

## 3. 方案比较

| 方案 | 做法 | 取舍 |
|---|---|---|
| **1. 采集端完全不接,协议不变(采用)** | 采集端删掉 Codex、dsh 的采集;状态帧照旧带 `cx=0 ds=0`;固件忽略这两个字段并去掉 Codex 页 | 做到只接 Claude,且版本可以任意搭配;协议里留两个恒为 0 的字段,需在文档注明 |
| 2. 连协议一起清理 | 状态帧去掉 `cx`、`ds`,固件删掉 CX/DS | 最干净;但旧固件收到新格式会整帧丢弃、显示未连接,采集端与固件必须同时更新 |
| 3. 只改画面 | 采集端照旧,只在固件里隐藏 | 改动最小;不符合“只接 Claude”,电脑上仍留着 Codex hook |

使用者选择方案 1。首页布局在三种设计稿中选了 A(只换底部三格,宠物与大数字不动),另两种是缩小宠物放两条进度条、以及把用量页升为首页。

## 4. 首页

```
AGENT RUN!            🔈 98% ▭
狂奔中
5  个会话在跑            速度 ▂▄▆█
┌──────────────────────────┐
│         (宠物场景)          │
└──────────────────────────┘
┌──────┐ ┌──────┐ ┌──────┐
│ 86%  │ │ 41%  │ │  1   │
│5 小时│ │ 每周 │ │后台运行│
└──────┘ └──────┘ └──────┘
今日完成 21              等你 0
```

- 三格依次为:5 小时用量、每周用量、后台运行。数据取自 Claude Code 的 A 帧(`h`、`w`、`bg`),与专用页面同源。
- 百分比 ≥ 80% 时用橙色,规则与专用页面的进度条相同;`bg` 为 0 时用暗色,与现在计数格为 0 时一致。
- 暂无数据(`h=-`,或还没收到 A 帧)与无此限额(`h=x`)都显示暗色 `--`。
- 标签用中文标签对象(专用页面已有 `s_tile_label`),文字为“5 小时”“每周”“后台运行”,字形都已在现有字库中,不需要重新生成字体。
- 大数字“N 个会话在跑”与跑速档位只按 `cc` 计算,忽略 `cx`、`ds`。
- 底栏“今日完成 / 等你”不变。

## 5. 页面切换

- 页面只剩首页与 Claude Code 页,上下键在两者间切换,页码点从 3 个变成 2 个。
- Claude Code 页面内容不变(套餐徽标、两张用量卡片含重置时间、工作中 / 后台运行 / 今日完成)。
- 等你处理、未连接时照旧显示首页对应画面。

## 6. 采集端

- `ar_hook.py`:只接受 `claude`。旧版装进 Codex 的 hook 若仍被调用,静默丢弃。
- `state.py`:`HOOK_TOOLS` 只剩 `claude`;删掉 dsh 扫描估算的入口。
- `daemon.py`:不再扫描 dsh;`AGENT_TOOLS` 只剩 `claude`,只发 `t=CC` 的 A 帧;演示模式的画面与示例数据只用 Claude(等你处理一屏改为两个 Claude 会话)。
- 状态帧与 `status.json` 照旧输出 `cx`、`ds`,恒为 0;`status.json` 的 `agents` 只含 `claude`。
- `usage.py`:删掉 Codex 会话文件的用量读取,只保留 Claude Code。
- `install.py` / `cli.py`:
  - `install-hooks` 只为 Claude Code 安装;同时移除 `~/.codex/hooks.json` 里 agent-run 自己的旧条目(修改前照旧备份到 `~/.agent-run/backup/`),其他条目不动。
  - `uninstall-hooks` 照旧清理 Claude Code 与 Codex 两处,保证旧安装也能清干净。
  - 删掉 `install-dsh-hooks` 命令与 `dsh.py`。
  - `status` 只显示 Claude Code;删掉 Codex 未信任 hook 的提示。
  - `status` 在两种残留时给出提示:`~/.codex/hooks.json` 里还有 agent-run 的条目(提示执行 `install-hooks` 或 `uninstall-hooks` 清掉);`~/.agent-run/dsh-hooks.json` 还在(提示到 dsh profile 的 `cordis.patch.yml` 里拿掉插件挂载,再删掉这个文件)。
- dsh 的插件挂载是使用者手写在 dsh profile 里的,采集端不自动修改 dsh 的配置,也不自动删除 `dsh-hooks.json`(插件找不到配置时的行为不在我们掌控内)。插件若仍挂载,`ar_hook.py dsh` 会被调用但静默丢弃。
- Codex 在 `~/.codex/config.toml` 里的 `[hooks.state."…"]` 信任记录保留不动:只是记录,没有对应 hook 时不会执行任何东西,而改写 TOML 没有解析器、风险大于收益。

## 7. 固件

- `ar_model.c`:工作中总数只算 `cc`;`ar_page_t` 去掉 `AR_PAGE_CX`。
- `ar_proto.c`:照旧解析 `cx`、`ds` 与等待列表里的 `CX`、`DS`(保持兼容规则),但界面不再使用 `cx`、`ds`;`t=CX` 的 A 帧照旧接受后忽略。
- `main.c`:首页也要拿到 Claude 的 A 帧数据(现在只在专用页面填 `view.agent`)。
- `ar_ui.c`:首页三格改画用量与后台运行;Codex 页不再出现。
- 旧采集端 + 新固件时,等待列表里的 `CX`、`DS` 项照旧处理:照常进入等你处理画面、响铃、在列表里显示工具名,底栏“等你 N”照旧用 `wn`。因此 `AR_TXT_TOOL_CX`、`AR_TXT_TOOL_DS` 保留,不重新生成字库,等待相关的规则与宿主测试不变。
- 固件版本升到 `0.7.0`。

## 8. 文件

- `docs/protocol.md`:注明 `cx`、`ds` 由本采集端恒发 0、展示端可以忽略;`t=CX` 不再发送。
- `README.md`:功能、支持情况、快速开始(去掉 Codex 信任与 dsh 两步)、命令参考、设备操作、已知限制、截图(首页与专用页面重拍,`scripts/readme_screens.py`)。
- `CLAUDE.md`:同步架构描述。

## 9. 测试与验收

- Python:hook 只认 `claude`;`install-hooks` 移除 Codex 旧条目且不动其他条目;状态帧 `cx=0 ds=0`;只发 CC 的 A 帧。
- 固件宿主测试:页面切换只在两页间循环;工作中总数只算 `cc`;三格的取值规则(含 ≥80%、`--`)若放在 `ar_model` 中则一并测试。
- 真机:首页三格显示正确;新采集端 + 旧固件、旧采集端 + 新固件都不出现“未连接”;LVGL 内存池余量记录在本文。

## 10. 留给实现者决定

- 三格百分比的像素字号:`100%` 在 3 倍字号下放不进 56 px 的格子,可以改用 2 倍字号或只在 100 时缩小。
- 三格取值规则放在 `ar_model.c`(可宿主测试)还是 `ar_ui.c`。
- 采集端 `__version__` 是否随之升级。
